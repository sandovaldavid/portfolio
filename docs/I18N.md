# Internationalization

The portfolio is bilingual. English is the default unprefixed locale and Spanish is served below `/es`.

## Routing contract

- `Astro.currentLocale` owns locale detection.
- `astro:i18n` owns ordinary localized URL generation.
- Missing Spanish content is an error, not an English fallback.
- Editorial counterparts are paired through stable translation identities rather than filename assumptions.

Do not restore manual locale-prefix parsing or the removed localization compatibility runtime.

## Content ownership

Each localized value has one owner:

- reusable UI, accessibility and metadata labels: `src/shared/config/i18n/locales/{locale}/`;
- profile records: localized structured Content Collection data;
- experience, research and project narratives: localized MDX Content Collections with stable frontmatter identity;
- blog and devlog bodies: localized editorial collections;
- URLs, assets, ordering, technology IDs and feature flags: language-neutral TypeScript data;
- markup, interactions and styling: Astro or TypeScript consumers.

Components must not become translation stores. They consume typed catalog APIs or entity APIs rather than importing locale JSON or Content Collections directly.

## Catalog rules

The UI catalog contains non-empty plain scalar strings only.

- English and Spanish module paths and key sets stay in exact parity.
- Use complete grammatical units rather than translated fragments.
- Register modules in the catalog owner.
- Missing or empty values fail loudly.
- Arrays, records and long-form narratives belong in schemas or Content Collections.
- Catalog strings must not contain HTML.

## Structured and editorial content

Localized records use immutable language-neutral IDs so English and Spanish entries can be validated and joined to shared technical metadata.

Research MDX keeps stable identity and Home-preview metadata in frontmatter while the scientific narrative remains in the MDX body. This prevents experimental sections, diagrams and future evidence from expanding the Content Collection schema into a rigid page model.

Blog and devlog entries use stable translation keys. A route exposes a language counterpart only when the matching published entry exists.

## Metadata and accessibility

Visible and non-visible copy follow the same locale ownership. This includes:

- titles, descriptions and social metadata;
- canonical and alternate URLs;
- JSON-LD and RSS language values;
- breadcrumbs, accessible names and image alternatives;
- screen-reader-only and control text.

Official names, technologies, URLs and stable IDs remain language-neutral when appropriate.

## Validation

Source-level validation:

```bash
bun run check:i18n
bun run check
```

Generated routes and browser behavior:

```bash
bun run build
bun run check:links
bun run test:e2e:smoke
```

The scripts under `scripts/i18n/`, Content Collection schemas and focused unit/browser tests are the detailed executable contract. Do not document allowlists, route matrices or catalog inventories separately from those sources.

## Prohibited patterns

Do not add:

- monolithic locale files or a second translation runtime;
- component-local bilingual copy maps;
- direct locale JSON imports outside the catalog owner;
- locale ternaries selecting complete messages;
- raw HTML translations;
- silent English fallback;
- duplicated language-neutral metadata;
- fabricated editorial counterparts.
