	<ExperiencePanel eyebrow="DEBUGGING" title="Debugging entre servicios y datos" emphasis>
		Cuando un problema cruza varias capas, sigo el flujo afectado entre callers, servicios y datos
		antes de decidir el cambio. Si el sistema no puede determinar de forma segura cuál es el estado
		correcto, prefiero un error explícito a devolver silenciosamente una respuesta plausible pero
		incorrecta.
	</ExperiencePanel>
	<ExperiencePanel
		eyebrow="AUTORIZACIÓN + INTEGRACIÓN"
		title="Autorización e integración entre servicios"
	>
		Los cambios de autorización y contrato pueden afectar a más de un consumidor. Reviso el tenant
		scoping y los callers que dependen del comportamiento para que backend, frontend y otros
		servicios evolucionen en conjunto cuando cambia un contrato.
	</ExperiencePanel>
</ExperienceSection>

<ExperienceSection eyebrow="VALIDACIÓN" title="Validación de regresiones" surface="highlight">
	Uso pruebas, feedback del compilador y análisis estático para identificar código afectado y
	comprobar el comportamiento que cambié. En cambios propensos a regresiones, a veces retiro
	temporalmente el cambio para confirmar que la nueva prueba falla por la razón esperada. Si nueva
	evidencia apunta a otra causa, actualizo el diagnóstico en lugar de mantener la primera
	explicación.
</ExperienceSection>
