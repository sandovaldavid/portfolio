<CaseStudySection
	eyebrow="LÍMITE DE EVIDENCIA"
	title="El cliente es público; la API compañera es privada"
>
	El repositorio público `MAD-AI` expone la aplicación Angular, la entrada SSR, la arquitectura
	cliente por capas y sus adaptadores HTTP. Un repositorio separado `MAD-AI-API` contiene el
	servicio Django REST, pero ese repositorio es privado. Este caso de estudio usa el backend
	privado como contexto verificable por el propietario y mantiene el badge de código público
	enlazado sólo al frontend que un reclutador puede inspeccionar de forma independiente.
</CaseStudySection>

<CaseStudySection
	eyebrow="PROBLEMA"
	title="Los flujos administrativos acumulan responsabilidades transversales rápidamente"
>
	Autenticación, navegación protegida, administración de usuarios, roles, notificaciones y
	reporting necesitan comportamiento compartido sin convertir los componentes en clientes de
	transporte. El proyecto separa estas responsabilidades en ambos extremos: un cliente Angular con
	capas explícitas y un servicio Django REST con sus propios límites de aplicación, dominio e
	infraestructura.
</CaseStudySection>

<CaseStudySection eyebrow="BACKEND" title="La API privada usa una arquitectura Django modular y pragmática" surface="highlight">
  El manifest del backend fija **Django 5.2.3** y **Django REST Framework 3.16.0**, con JWT/cryptography, PostgreSQL mediante `psycopg2`, filtering, tooling OpenAPI y Celery. Su documento de arquitectura describe un enfoque híbrido modular que combina service layer, modelos Django centrados en dominio y ports/adapters en lugar de forzar un dominio agnóstico que duplique el ORM.

Como el repositorio es privado, estos datos no se presentan como evidencia pública inspeccionable de forma independiente. Explican la arquitectura que construí y mantengo; el cliente público sigue siendo la superficie que un revisor externo sí puede verificar.

</CaseStudySection>

<CaseStudySection eyebrow="REPORTING" title="El cliente posee visualización y exportación">
	El manifest Angular incluye ECharts, jsPDF y PapaParse. Mantener charting y exportación en el
	cliente permite convertir respuestas de API en visualizaciones interactivas y representaciones
	descargables sin devolver preocupaciones de presentación al servicio REST.
</CaseStudySection>
