<CaseStudySection eyebrow="CURRENT SYSTEM" title="Stable 3.1.2 release with active development continuing">
	Kioku is distributed as a public .NET project with release artifacts, a NuGet package and operational documentation. Version **3.1.2** is the current stable tagged server release, while ongoing work continues toward later releases.
</CaseStudySection>

<CaseStudySection eyebrow="PROBLEM" title="Agent context should survive the session that created it">
  Coding agents can make good decisions and still lose the reasoning behind them when a process, terminal or conversation ends. Provider history is not a durable project record, and a handoff should not require the next agent to reconstruct intent from chat logs.

Kioku treats the vault as durable project memory instead: specs, implementation plans, decisions, bugs, knowledge and session handoffs remain readable as Markdown and YAML even without the MCP server or Obsidian UI running.
</CaseStudySection>

<CaseStudySection eyebrow="ENGINEERING DECISIONS" title="Keep storage human-readable and protocol boundaries explicit">
  <CaseStudyGrid columns={3}>
    <CaseStudyCard label="DECISION 01" title="MARKDOWN IS THE DURABLE FORMAT" tone="primary">
      The vault remains understandable and editable without Kioku. The MCP layer coordinates workflows; it does not become the only place where project knowledge can be recovered.
    </CaseStudyCard>
    <CaseStudyCard label="DECISION 02" title="HEADLESS CORE, OPTIONAL UI" tone="primary">
      Core notes, search, projects, sessions, indexing and coordination work directly against the vault. Obsidian and its companion plugin are optional for UI and bridge-specific operations.
    </CaseStudyCard>
    <CaseStudyCard label="DECISION 03" title="REMOTE ACCESS REQUIRES AN EXPLICIT TRUST BOUNDARY" tone="primary">
      Local stdio stays the default. Streamable HTTP binds to loopback by default, and non-loopback exposure requires authentication unless an explicit unsafe override is chosen.
    </CaseStudyCard>
  </CaseStudyGrid>
</CaseStudySection>

<CaseStudySection eyebrow="LEARNINGS" title="What this project changed in how I build" surface="highlight">
  <CaseStudyGrid columns={3}>
    <CaseStudyCard label="LEARNING 01" title="DURABILITY BEATS PROVIDER HISTORY" tone="success">
      Human-readable project records survive session and process boundaries better than depending on one AI provider's conversation history.
    </CaseStudyCard>
    <CaseStudyCard label="LEARNING 02" title="SPEC → PLAN → SESSION IS A USEFUL BOUNDARY" tone="success">
      Keeping requirements, implementation intent and execution state separate makes a fresh agent more likely to continue the right work instead of merely continuing text.
    </CaseStudyCard>
    <CaseStudyCard label="LEARNING 03" title="LOCAL-FIRST DOES NOT REMOVE SECURITY WORK" tone="success">
      The moment a local protocol becomes remotely reachable, authentication, origin policy, proxy trust and vault boundaries become first-class engineering concerns.
    </CaseStudyCard>
  </CaseStudyGrid>
</CaseStudySection>
